## Hazards: read before launching anything

- **The installed Dvsk.** `/Applications/Dvsk.app` is normally running. On 2026-10-13 it was PID 87858, started 2026-10-11 23:00, version 0.1.1 (build 2), Developer ID signed (Fabian General, team 4RGKC487ZB), hardened runtime, notarized and stapled, and it has no "Launch at login" item because it predates DVSK-001. Two copies fight over the display gamma tables.
- **Check with `pgrep -x Dvsk`** (exact process name: prints the PID, or nothing). Do not use `pgrep -fl -i dvsk`: it also matches the Claude processes, whose command line contains `--project-config-root /Users/fwgl/dev/dvsk`.
- **Never, while the installed copy runs:** `swift run Dvsk`, `open /Applications/Dvsk.app`, `open build/Dvsk.app`, or `./scripts/bundle.sh` followed by a launch. Never quit or replace the installed copy. Ask the user with a `[user]` question and mark those checks Not verified.
- **`build/Dvsk.app` in the project can be stale.** On 2026-10-13 it was an ad-hoc signed 0.1.0 build from 2026-10-11, without DVSK-001. `bundle.sh` deletes and rebuilds it. DVSK-001 did not bump the version (`AppInfo.plist` stays 0.1.1), so the version number cannot tell the new build from the installed copy: look for the "Launch at login" menu item.
- **Login Items.** QA never registers or unregisters a login item and never changes System Settings. The Login Items list, log-outs and log-ins are the user's. `swift test` is safe because it uses a fake `LoginItemService`.
- **No ports, no network, no browser.** Dvsk opens no socket and makes no network call. Playwright does not apply.
- **Do not edit the project from QA.** Experiments (mutations, release builds, coverage) run in a scratch copy outside the project. `swift build` and `swift test` in the project only refresh its gitignored `.build`.

## Method notes (reusable)

- **Scratch copy.** `rsync -a --exclude .build --exclude build --exclude .git --exclude .swiftpm --exclude .claude --exclude docs /Users/fwgl/dev/dvsk/ <scratch>/pristine/`, then compare `shasum -a 256` of the changed files with the project's before trusting a result. The scratch folder used on 2026-10-13 was `/private/tmp/claude-501/-Users-fwgl-dev/f4a2b1bf-766b-4572-92e8-c111704bb241/scratchpad/dvsk-qa` (session-specific; recreate it).
- **Mutation check** (do the tests have teeth?). In a second scratch copy, change one line of `Sources/DvskCore/LoginItem.swift`, run `swift test --filter LoginItemTests --package-path <copy>`, and expect the targeted test to fail. 2026-10-13, all nine caught: needs-approval shown as on (M1), not-found shown as off (M2), enabled shown as off (M3), not-registered shown as on (M4), state remembered after the first read (M5, `testStateFollowsSystemSettingsAndIsNeverRemembered`), reading the state registers (M6, `testReadingNeverRegistersOrUnregisters`), not-found not tried on a click (M7), register tried while approval is pending (M8, `testPendingApprovalIsNotRegisteredAgain`), a click judged by whether the call threw instead of the re-read status (M9). M1 to M4 each fail `testReadsEachSystemStatusAsAnOptionState` among others.
- **Coverage.** `swift test --enable-code-coverage --package-path <copy>`, then `swift test --show-codecov-path --package-path <copy>` for the JSON. 2026-10-13: `LoginItem.swift` 45 of 47 lines, 6 of 6 functions. The two lines left are the last fallback message in `setOn` (lines 91 and 92: the call returned, the status did not change and no reason is known). Reading the state is fully covered.
- **App-bundle test expression.** `SystemLoginItemService.runsAsAppBundle` is `Bundle.main.bundleURL.pathExtension == "app"`. Foundation-only check on 2026-10-13: `Bundle(path:)` URLs of real `.app` bundles end in `.app/` and give `pathExtension` `app` (true); a plain directory, as under `swift run`, gives an empty extension (false). So the guard does not lock out the installed app.
- **Gamma readback (not written yet).** To see a tint without a screenshot, call `CGGetDisplayTransferByTable` for each active display in a small Swift script kept outside the project, and compare with the identity ramp. Run it only when the user allows a Dvsk to run, and never start a Dvsk for it.
